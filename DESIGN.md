## Brand & Style

The design system is an exercise in **Precision Minimalism** and **Technical Sophistication**. It is designed for high-density information environments—research, engineering, and data-driven operations—where clarity is the primary utility.

The aesthetic is inspired by the "structured technical manuscript": a refined, tactile digital surface that prioritizes quiet control over visual noise. The target audience consists of professionals who require deep focus and low cognitive load during intensive sessions. The design style avoids heavy shadows and aggressive borders, relying instead on high-precision typography and subtle tonal shifts to delineate information architecture.

The system ships as two coordinated palettes under the same token vocabulary:

- **Light — Slate & Syntax:** A high-clarity, cool-toned light base that evokes professional transparency and alertness.
- **Dark — Slate & Syntax: Night Edition:** A deep, low-glare dark canvas optimized for prolonged focus sessions. Surfaces sink darker instead of inverting to pure black, and accent colors shift to cooler, brighter tones to maintain contrast without harshness.

## Theming

This design system uses **CSS custom properties** for mode switching. All colors in the YAML frontmatter above are mapped to `--color-*` tokens in `styles.base.css`:

```
--color-primary       → primary (light: #1b4490, dark: #c3e7ff)
--color-background    → background (light: #faf8ff, dark: #0c1325)
--color-on-surface    → on-surface (light: #1a1b20, dark: #dce1fb)
```

### Mode Switching

- Light mode is the default (`:root` / no class).
- Dark mode is activated via `html.dark` on the document element.
- The `styles.base.css` file contains `html.dark { ... }` overrides for every token.
- In components and templates, **always reference the semantic CSS variable** (e.g., `var(--color-primary)`), never hardcode raw hex values for backgrounds or text colors.

### What Changes Between Modes

| Property          | Light Mode                                                                 | Dark Mode                                                                             |
| ----------------- | -------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| Surfaces          | Get progressively darker as they rise (tonal stacking). Base is brightest. | Surfaces sink darker. Base is deepest. Container ladder ascends toward lighter tones. |
| Text              | Dark on light (`#1a1b20` on `#faf8ff`)                                     | Light on dark (`#dce1fb` on `#0c1325`)                                                |
| Primary accent    | Deep blue (`#1b4490`)                                                      | Cool cyan/blue (`#c3e7ff`)                                                            |
| Primary container | Medium blue (`#385ca9`)                                                    | Bright cyan (`#7bd0ff`)                                                               |
| Borders           | Visible at `outline-variant` opacity                                       | More visible (lighter opacity). Use `outline-variant` for subtle separators.          |
| Shadows           | Subtle lift (`rgb(26 27 32 / 0.08)`)                                       | Heavier depth signal (`rgb(0 0 0 / 0.5)`) with a `0 0 0 1px` wrapper for separation   |
| Selection         | `primary-container` background                                             | `color-mix(in srgb, primary 30%, transparent)` for softer highlight                   |
| Images            | Full brightness (`opacity: 1`)                                             | Reduced brightness (`opacity: 0.9`) on photographic content                           |

### What Stays the Same

- Typography (font families, sizes, weights, line-heights)
- Border radii and spacing scale
- Motion durations and easing curves
- Component structure and layout contracts
- Semantic token names — `--color-primary` means the same role regardless of mode

### Agent & AI Guidance

When generating components with this DESIGN.md:

- **Always** use semantic token names (`var(--color-surface)`, `var(--color-on-surface)`, `var(--color-primary)`), never raw hex values.
- **Always** add `dark:` variants for any color that differs between modes when using Tailwind classes. Reference the token table above for correct dark values.
- **Prefer** CSS custom properties over inline Tailwind arbitrary values (`bg-[var(--color-surface)]` over `bg-[#faf8ff]`).
- **Do not** hardcode `#ffffff` or `#000000` for backgrounds — use surface container tokens.
- **Shadows** must use the correct token per mode: `var(--shadow-panel)`.
- **Selection** styles must include a `html.dark` variant.
- The mode toggle is handled by the application shell — components should not generate mode-toggle logic.

## Colors

### Light Mode — Slate & Syntax

This color palette transitions from clean, high-energy foundations to precise technical highlights. The primary **Technical Blue (#1b4490)** acts as the anchor for all interactive elements, providing a clear visual signal against the light operational surfaces.

- **Primary:** Reliable, clear-view technical blue (`#1b4490`), with container at `#385ca9`.
- **Secondary:** Muted slate (`#535f70`) for utility and supporting metadata.
- **Neutral:** Crisp whites and light greys derived from the surface base to maintain a unified temperature.
- Depth is created through **tonal stacking**: elements that rise in hierarchy (modals, popovers, active panes) become subtly darker container tints.

### Dark Mode — Slate & Syntax: Night Edition

The dark palette shifts the base to a deep blue-black canvas (`#0c1325`) and lifts accent colors toward cooler, brighter values.

- **Primary:** Cool cyan (`#c3e7ff`), with container at `#7bd0ff`.
- **Secondary:** Mint/teal (`#9ad1c6`) for softer utility signals.
- **Neutral:** A range of deep navy surfaces (`#070d1f` → `#2e3448`) that rise toward lighter tones as they gain elevation.
- **Surface hierarchy inverted:** The deepest surface is the base canvas; containers become progressively lighter as they approach the user.

### Usage Rules

- Use `background`/`surface` for full-page canvases.
- Use the surface-container ladder to communicate hierarchy:
  ```
  lowest → low → default → high → highest
  (canvas)    (nav rail)  (content)  (action panel)  (transient popover)
  ```
- `primary` appears on buttons, active navigation, focus rings, progress, and agent signals.
- `secondary` supports non-primary actions and metadata.
- `tertiary` and `success` indicate domain state.
- `error` must only signal failures, destructive actions, or blockers.

## Typography

The typography system uses a tri-font strategy to separate intent across modes.

1. **Manrope (Headlines):** Structural navigation and page titles. Its modern, geometric curves provide a humanistic touch to an otherwise technical layout.
2. **Inter (Body):** The workhorse for all prose, data entries, and descriptions. Exceptional legibility and neutral character.
3. **JetBrains Mono (Labels/Technical):** Machine-readable content, status tags, timestamps, and code snippets. Reinforces the "structured manuscript" aesthetic.

Hierarchy is maintained through consistent weight application across both modes.

## Layout & Spacing

Fixed-Fluid Hybrid Grid built on an 8px base unit.

- **Desktop:** 12-column grid, container max 1440px, 48px margins.
- **Tablet:** 8-column grid, 24px gutters.
- **Mobile:** 4-column fluid grid, 16px margins.

Spacing favors "loose-internal, tight-external": elements within a logical group stay close; groups are separated by significant whitespace.

## Elevation & Depth

Depth is communicated through **Tonal Layering** and **Micro-Borders**, not traditional drop shadows.

| Mode  | Strategy                                                                                                                                                    |
| ----- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Light | Base is brightest surface. Rising components gain progressively darker container tints. Use subtle shadows only for overlay panels.                         |
| Dark  | Base is deepest surface. Rising components gain progressively lighter container tints. Use `--shadow-panel` plus a 1px ghost border for overlay separation. |

- Ghost borders: `outline-variant` at low opacity (`rgb(from var(--color-outline-variant) r g b / 0.28)`).
- Avoid heavy drop shadows for structural hierarchy.
- `--shadow-panel` is reserved for modals, drawers, active nav, and auth panels.

## Shapes

Consistently **Rounded (0.5rem base)** across both modes.

- **Standard (Buttons, Inputs, Cards):** 0.5rem (8px).
- **Large Containers (Modals, Sidebars):** 1rem (16px).
- **Small Utilities (Tags, Badges):** 0.25rem (4px).

## Motion

Motion clarifies state changes, not decoration.

- Fast: 100ms (hover, focus)
- Base: 200ms (sidebar toggle, layout transitions)
- Enter: 300ms ease-in-out (page transitions, panel enters)
- Respect `prefers-reduced-motion` — disable non-essential transforms/animations.

## Components

### Buttons

- **Primary:** `background: var(--color-primary)`, `color: var(--color-on-primary)`, radius 0.5rem, font-weight 700.
- **Secondary:** Transparent or tonal surface with outline-variant ghost border.
- **Text/Link:** Primary color, semibold, underline only on hover.
- **Disabled:** Reduce opacity; do not rely only on color change.

### Inputs & Forms

- Inputs are recessed wells: transparent or tonal background, quiet ghost bottom border.
- Focus: primary-colored ring, transparent border.
- Labels: Inter semibold, 14px.
- Help/error copy below fields using `on-surface-variant` or `error` tokens.
- Dark mode: inputs use `surface-container-high` background; autofill respects theme.
- Auth forms: explicit labels, stable button names, accessible autocomplete attributes.

### Cards

- No shadows. Use tonal shift to next container level or 1px subtle border.
- Treat cards as recessed records, not floating marketing cards.
- Compact padding; tonal backgrounds.

### Navigation

- Sidebar: `surface-container-low` or `surface-container-lowest`.
- Active nav: tonal surface elevation, subtle shadow, primary left border.
- Section labels: uppercase, tracked, low contrast.
- Mobile nav: full-height overlay with dim backdrop.

### Chips & Status

- JetBrains Mono for text within chips.
- Muted, de-saturated background tints.
- Small, rounded, high-signal status badges.

### Lists

- Use 1px dividers only when data density is extremely high.
- Otherwise, separate list items with vertical spacing.

## Anti-Patterns

- Do not use raw hex values for backgrounds or text — always use `var(--color-*)` tokens.
- Do not hardcode `#ffffff` or `#000000` as surface colors.
- No aggressive purple gradients, warm beige AI canvases, or decorative emoji icon rows.
- No heavy shadows for structural hierarchy.
- No rounded cards with decorative left-color stripes unless the stripe is an active/status signal.
- No anonymous metric grids or fake performance numbers.
- Do not generate mode-toggle logic; it belongs to the application shell.
