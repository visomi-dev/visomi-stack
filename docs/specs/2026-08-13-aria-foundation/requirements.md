# Aria Foundation — Requirements

## In Scope

1. **`@angular/aria@22.1.2`** is added as a workspace dependency. `@angular/cdk` is bumped from 22.0.2 to 22.1.2 to match the `listbox` subpath export that `@angular/aria` depends on.
2. **`app-listbox`** is migrated to wrap `@angular/cdk/listbox`'s `cdkListbox` and `cdkOption` directives. The public API (`selector: 'app-listbox'`, `ariaLabel`, `options`, `valueChange`, `ControlValueAccessor` contract, `disabled` state, class names) is unchanged. The new component is shorter, supports arrow navigation, typeahead, and Home/End keys for free, and is unit-tested.
3. **`app-sidebar-menu`** is reshaped to a Nive-style layout: brand at the top, primary nav in the middle, footer at the bottom that contains the user identity, a theme toggle, and an explicit `Sign out` button. The previous user-menu dropdown is removed. The sign-out button is the canonical way to end a session from the shell and it carries the `data-od-id="sidebar-sign-out"` hook for the e2e suite.
4. **Component catalog** lives at `docs/design-system/components.json` and `docs/design-system/components.md`. It is generated by `scripts/generate-component-catalog.mjs` from the `apps/web/app/src/app/shared/ui` source tree. It lists every primitive, its selector, source path, template path, style path, whether it implements `ControlValueAccessor`, its signal inputs, and its outputs.
5. **Gallery route** at `/app/en/gallery` is reachable only after authentication. It renders one card per primitive, with a live preview, a title, and a one-line description. It has a left rail with section links and a search input that filters cards by title, description, or selector.
6. **E2E coverage** is added in `apps/web/app-e2e/src/app/sidebar.spec.ts` and `apps/web/app-e2e/src/app/gallery.spec.ts`. The sidebar suite asserts the `Sign out` button is visible, that the button is still visible when the sidebar is collapsed (with the text label visually hidden), that the active section is highlighted, and that clicking `Sign out` redirects to `/sign-in`. The gallery suite asserts the page renders, the filter narrows results, and the listbox supports keyboard navigation and selection.
7. **Snapshot evidence** is captured by `scripts/capture-aria-foundation.cjs`. The script bootstraps a real session through the public sign-up + OTP endpoints, then captures `media/aria-foundation/*.png` at 390×844 (mobile) and 1280×800 (desktop) for sign-in, dashboard, projects, gallery, and sidebar-collapsed (desktop only), in light and dark.

## Out of Scope

- The combobox is **not** migrated. It is not yet consumed by any route. The `@angular/aria` combobox requires a `ng-template` popup with deferred content, which is a bigger refactor that does not earn its cost on a 0-consumer primitive.
- The `app-dropdown` and `app-tooltip` are **not** migrated. They already work with the CDK overlay and do not yet have an `@angular/aria` equivalent that matches the current API. The dropdown is the wrapping element for the listbox; it is exercised by the gallery.
- The catalog generator is **not** extended to lerna-style versioning or to a published `llms.txt`. The `components.json` is the contract for now.
- No new tokens are added. The sidebar, the gallery, and the listbox all stay inside the Catalyst token set.
- No new tests are added for the catalog generator itself. It is a build-time script; the e2e suite and the gallery snapshots catch regressions in the consumer surface.
